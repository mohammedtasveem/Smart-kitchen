1. Project Overview

Q: What is Smart Kitchen?
Smart Kitchen is a full-stack web application that helps users track food items in their kitchen, monitors expiry dates, and sends automated WhatsApp alerts when items are about to expire or have already expired. It also recommends recipes based on the ingredients available, helping reduce food waste.
Q: What problem does it solve?
According to the Food and Agriculture Organization (FAO), approximately 1.3 billion tons of food is wasted globally every year. At the household level, a significant portion of this waste occurs because people forget about food items stored in their kitchen until they expire. Smart Kitchen addresses this by providing automated monitoring and real-time WhatsApp notifications.

2. Problem Statement

Q: What is the problem statement?
Households lack an efficient system to track perishable food items and their expiry dates. This leads to:
  • Significant food waste due to forgotten or overlooked items
  • Health risks from consuming expired food
  • Financial loss from repurchasing items that were already available
  • No automated mechanism to alert users before food expires
The goal is to build an intelligent system that monitors food inventory, classifies items by expiry status, sends timely WhatsApp alerts, and suggests recipes to use ingredients before they expire.

3. Proposed Solution

Q: What is the proposed solution?
Smart Kitchen is a cloud-deployed full-stack web application with the following components:
  • Web Dashboard: React-based frontend for managing food inventory, viewing alerts, and browsing recipes
  • REST API: Express.js backend handling authentication, CRUD operations, and business logic
  • Automated Expiry Sweep: Cron job that runs daily at 8:00 AM IST to check for expiring/expired items
  • WhatsApp Alert System: Sends grouped expiry alerts via Meta's WhatsApp Cloud API using approved message templates
  • Recipe Recommendation Engine: Matches available ingredients against a recipe catalogue, prioritizing items closest to expiry
  • Cloud Database: MySQL-compatible TiDB Cloud for persistent data storage

4.1 Why These Technologies Were Chosen

Q: Why React for the frontend?
React was chosen for its component-based architecture, which allows building reusable UI components. The virtual DOM provides efficient rendering, and the large ecosystem offers libraries for routing (React Router), state management, and API calls. Vite was used as the build tool for its fast development server and optimized production builds.
Q: Why Node.js + Express for the backend?
Node.js was chosen because the project already uses JavaScript on the frontend, allowing a unified language across the full stack. Express.js provides a minimal, flexible framework for building REST APIs. Node's non-blocking I/O model is ideal for handling concurrent API requests and cron jobs efficiently.
Q: Why TiDB Cloud instead of MySQL or MongoDB?
TiDB Cloud provides a MySQL-compatible serverless database with a free tier. It offers the relational structure of MySQL (ideal for structured data like users, food items, and notifications) without requiring server management. The MySQL compatibility meant zero code changes from a local MySQL setup. MongoDB was considered but rejected because the data is inherently relational (users own food items, food items generate notifications).
Q: Why WhatsApp for alerts instead of email or SMS?
WhatsApp has over 500 million users in India and is the most widely used messaging platform. Unlike email, WhatsApp messages have a 98% open rate versus 20% for email. Compared to SMS, WhatsApp is free (via Meta Cloud API), supports rich formatting, and reaches users where they are most active. Meta's WhatsApp Business API provides 1000 free messages per month for testing.

5. System Architecture

Q: Describe the system architecture.
The application follows a three-tier architecture:
  • Presentation Layer (Frontend): React SPA hosted on Vercel, communicates with the backend via REST API calls
  • Application Layer (Backend): Express.js server hosted on Render, handles authentication, business logic, cron jobs, and WhatsApp integration
  • Data Layer (Database): TiDB Cloud MySQL database storing users, food items, notifications, and recipes

Data Flow:
  1. User adds/edits food items via the React dashboard
  2. Frontend sends API requests to the Express.js backend
  3. Backend validates, processes, and stores data in TiDB Cloud
  4. Daily cron job (8:00 AM IST) sweeps expiring items and creates notification records
  5. Dispatch cron job (8:05 AM IST) sends grouped WhatsApp alerts via Meta Cloud API
  6. Recipe matcher suggests dishes based on available ingredients and expiry priority

  4. If template fails, falls back to free-form text
  5. Delivery status is tracked in the notifications table

12. Security Measures

Q: What security measures are implemented?
  1. Password Hashing: Passwords are hashed using bcrypt with salt rounds before storage. Plain-text passwords are never stored.
  2. JWT Authentication: Stateless token-based authentication. Tokens expire after 7 days.
  3. Rate Limiting: Auth endpoints (login, signup) are limited to 5 attempts per 15 minutes per IP to prevent brute-force attacks.
  4. CORS: Cross-Origin Resource Sharing is configured to allow only the Vercel frontend domain.
  5. Input Validation: All user inputs are validated and sanitized to prevent XSS attacks.
  6. SSL/TLS: Database connections use SSL encryption. All API communication uses HTTPS.
  7. Environment Variables: All secrets (JWT_SECRET, database password, API keys) are stored in environment variables, never in code.
  8. .gitignore: The .env file is excluded from version control to prevent secret leakage.

17. Frequently Asked Questions (Viva Q&A)

Q1: What is the difference between your project and existing apps like fridgePal or NoWaste?
Most existing apps require manual input and only send in-app notifications. Smart Kitchen integrates directly with WhatsApp — the most used messaging app in India — ensuring alerts are seen immediately. It also features a recipe recommendation engine that suggests dishes based on expiring ingredients, which most competitors lack.
Q2: How does the recipe matching algorithm work?
The algorithm scores each recipe based on:
  1. Ingredient overlap: How many recipe ingredients are available in the user's inventory
  2. Expiry priority: Items closest to expiry get higher weight, encouraging use before waste
  3. Coverage ratio: Percentage of recipe ingredients available
Recipes are ranked by score and the top matches are displayed. This ensures users are prompted to use items that are about to expire first.
Q3: Is the application scalable?
Yes. The three-tier architecture separates concerns:
  • Frontend: Vercel's CDN handles millions of requests
  • Backend: Render supports horizontal scaling; can migrate to AWS/GCP for production
  • Database: TiDB Cloud auto-scales with serverless architecture
The modular codebase allows adding new features without affecting existing ones.
Q4: Why did you choose Meta WhatsApp Cloud API over Twilio?
Meta's WhatsApp Cloud API is the official, first-party route. It provides:
  • A free test phone number
  • 1000 free test messages per month
  • No per-message charges during development
Twilio charges per message from the start and acts as a middleman. For an academic project with zero budget, Meta's direct API was the natural choice.
Q5: How do you handle the case when a user's phone is off or WhatsApp is not installed?
The system tracks delivery status via the notifications table. If a message fails:
  • Transient errors (network issues, rate limits): The alert stays in "pending" status and retries on the next dispatch cycle
  • Permanent errors (number not on WhatsApp, invalid number): The alert is marked as "failed" with the error reason logged
The user can view all alert statuses on the Alerts page.
Q6: What happens if the Render server goes down?
  • Free tier Render services sleep after 15 minutes of inactivity
  • The first request takes ~50 seconds to wake the server
  • After waking, the server resumes normal operation
  • The database (TiDB Cloud) is always available, so no data is lost
  • Cron jobs resume automatically once the server is awake
Q7: How is this different from a simple reminder app?
Unlike simple reminder apps that require users to set individual reminders, Smart Kitchen:
  • Automatically classifies items by expiry status (FRESH / NEAR_EXPIRY / EXPIRED)
  • Groups alerts — sends one consolidated WhatsApp message per user, not one per item
  • Recommends recipes based on what's about to expire, turning waste prevention into meal planning
  • Runs autonomously — no user action needed after adding items; daily sweep + dispatch is automatic
Q8: What are the limitations of the current system?
  • Manual data entry: Users must manually add food items (Phase 10 with ESP32-CAM will address this)
  • Development mode: WhatsApp messages limited to 5 whitelisted numbers
  • Render cold start: Free tier server sleeps after 15 min, causing 50-second delay on first request
  • No barcode scanning: Cannot scan product barcodes for auto-entry
  • Single-currency recipe data: Recipe catalogue is pre-seeded, not user-contributed
Q9: How does the brute-force protection work?
The rate limiter uses a sliding window approach:
  • Maximum 5 login attempts per IP address within a 15-minute window
  • After 5 failed attempts, the IP is temporarily blocked
  • The window resets after 15 minutes
  • This prevents automated password guessing while allowing genuine users who mistype
